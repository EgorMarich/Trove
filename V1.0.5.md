# Trove v1.0.5 — Real Provider Booking Sandbox Boundary

## Delivered
- Booking.com Demand API v3.2 native accommodation order adapter.
- Native provider preview integrated into Trove booking preview when enabled.
- Provider order token, expiry, payment metadata and cancellation policy persisted on the Trove booking.
- Booking.com `/orders/preview` and `/orders/create` boundary.
- Booking.com `/orders/details/accommodations` reconciliation boundary.
- Provider registry now exposes Booking.com as a native booking provider when credentials + feature flag are enabled.
- Booking provider interface now supports preview and reconciliation.
- Native booking remains disabled by default.
- Payment timing/method are explicit environment settings; no card data is stored by Trove.
- Recovery can reconcile an existing provider order before scheduling another retry.

## Important
Booking.com Demand API v3.2 requires an API key and Affiliate ID. Native accommodation booking availability also depends on the partner account and endpoint access. The code defaults to sandbox and `BOOKING_NATIVE_BOOKING_ENABLED=false`.

The current Trove payment module is still a mock payment boundary. Therefore online card payment should not be enabled through the provider adapter until a real payment integration and the corresponding Booking.com payment method flow are implemented.
