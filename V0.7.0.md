# Trove v0.7.0 — Booking Engine

## Delivered
- Authenticated booking flow inside Trove.
- Booking domain/store/service.
- Provider offer lookup and mandatory price recheck before booking creation.
- Idempotency-Key protection against duplicate booking creation.
- Passenger/contact data collection.
- User-owned booking list, detail and cancellation endpoints.
- Payment boundary: bookings are `pending_payment`; Trove stores no card data.
- Mock Provider A marked as native-booking capable for the demo flow.
- Frontend booking form and My Trips pages.
- Offer detail CTA now chooses native Trove booking when provider supports it, otherwise keeps redirect flow.
- Security audit event for booking creation and booking rate limiting.

## Production follow-up
- PostgreSQL persistence.
- Redis-backed idempotency/rate limiting.
- Real provider booking adapters.
- Real payment provider + webhook verification.
- Provider cancellation/refund mapping.
- PII encryption/retention policy and stronger schema validation.
