# Trove v1.0.1 — Provider Registry & Native Booking Boundary

## Delivered

- Added `GET /api/providers/health` for provider readiness/capability visibility.
- Added explicit provider registry health statuses: `ready`, `disabled`, `degraded` boundary.
- Added a dedicated Booking.com Demand API v3.2 order client.
- Added server-side `/orders/preview` boundary.
- Added server-side `/orders/create` boundary.
- Added 15-minute order-token lifetime metadata.
- Added `BOOKING_NATIVE_BOOKING_ENABLED=false` feature flag.
- Kept native provider booking separate from Trove's internal booking record.
- Added provider integration documentation and production safety notes.

## Booking.com flow

```text
Search
  ↓
Availability
  ↓
/orders/preview
  ↓
Final price + policies + order_token
  ↓
Trove confirmation/payment boundary
  ↓
/orders/create
  ↓
Provider order
  ↓
Trove booking confirmation
```

Booking.com Demand API v3.2 documents `/orders/preview` as the validation step that returns final pricing/payment information and an `order_token`; `/orders/create` consumes that token. The token expires after 15 minutes.

## Important

Native booking remains disabled by default until real Booking.com credentials and the required partner access are configured. No provider booking is represented as confirmed merely because a Trove booking record was created.
