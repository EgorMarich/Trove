# Trove v1.0.7 — Payment Adapter & Webhooks

## Delivered

- Provider-agnostic `PaymentProvider` interface.
- Mock payment provider with checkout reference, lookup and cancellation boundary.
- Webhook-first payment state transition.
- HMAC-SHA256 webhook verification for the mock provider.
- Idempotent webhook event handling.
- Provider reconciliation for `unknown` payment state.
- Payment intent creation now creates a provider payment reference.
- Payment confirmation no longer directly marks a payment as paid; the webhook/reconciliation path owns that transition.
- No card data is stored by Trove.

## API

- `POST /api/payments/intents`
- `POST /api/payments/intents/:id/confirm`
- `POST /api/payments/intents/:id/reconcile`
- `POST /api/payments/webhooks/mock`
- `GET /api/me/payments/:id/events`

## Provider contract

```text
PaymentProvider
  createPayment()
  getPayment()
  cancelPayment()
  verifyWebhook()
```

## Production follow-up

Replace `mock-payment` with a real PSP adapter. Verify provider signatures, timestamps/nonces and replay windows according to the PSP contract. Prefer hosted/tokenized checkout. Keep provider payment IDs and immutable payment events for reconciliation.
