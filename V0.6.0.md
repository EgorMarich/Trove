# Trove v0.6.0 — Personalization

## Delivered

- Authenticated personalization module.
- Favorites API: add/remove and list by user.
- Viewed-offer history, capped to the latest 30 unique offers.
- Saved searches with per-user ownership and deletion.
- Basic travel preferences model and update endpoint.
- Frontend favorite controls on tour cards and offer detail.
- Authenticated favorites page.
- Account page sections for interests and saved searches.
- Offer detail records a view for the signed-in user.

## API

- `GET /api/me/personalization`
- `POST /api/me/favorites/:tourId`
- `POST /api/me/viewed/:tourId`
- `POST /api/me/saved-searches`
- `DELETE /api/me/saved-searches/:id`
- `PATCH /api/me/preferences`

## Storage

Current implementation uses in-memory stores to keep the development package dependency-light. Production persistence should move user personalization to PostgreSQL, with Redis reserved for sessions, rate limiting, caching and short-lived workflows.
