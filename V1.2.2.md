# Trove v1.2.2 — Beta Launch Hardening

## What changed
- Added server-side booking consent persistence with terms/privacy document versions.
- Booking preview/direct booking APIs now require explicit consent metadata.
- Consent is stored with booking ID, user ID, versions, timestamp, IP hash and user-agent.
- Added launch migration `006_launch_hardening.sql`.
- Reworked DB migration runner to track applied migration filenames in `schema_migrations` instead of replaying every SQL file on each run.
- Booking cancellation now refuses provider-backed `confirmed`/`provider_booking` states instead of pretending local cancellation is enough.
- Checkout analytics now fires only after client-side validation passes.

## Verification
- Static source checks: to be run after packaging.
- Full TypeScript/build/test suite cannot be claimed without installed dependencies in the working copy.
