# Trove v1.2.7 — Real Provider Integration

## Goal
Move from mock-only beta validation toward a controlled real-provider environment without pretending that credentials or access are configured.

## Added
- Booking.com transport timeout and provider request-id propagation.
- YooKassa API timeout handling.
- Real-beta preflight that refuses mock payments and validates HTTPS, Booking.com credentials/configuration, YooKassa credentials, and payment return URL.
- `pnpm real:preflight` root command.
- `pnpm test:real-preflight` backend command.

## Provider flow
Booking.com Demand API v3.2 accommodation booking follows:
`search/availability → orders/preview → orders/create → orders/details`.
The order preview token is short-lived, so the application must preview again when the token expires or booking context changes.

## Run
With real credentials loaded in the environment:

```bash
pnpm real:preflight
pnpm --dir backend test:booking-sandbox
```

The preflight never creates a YooKassa payment. It only authenticates against the API. Booking sandbox integration may create a sandbox order, so run it only with an account/test property intended for integration testing.

## Verification limitation
This release was validated with source/static checks in the current environment. Full TypeScript compilation and live provider calls require installed Node dependencies and real provider credentials/access.
