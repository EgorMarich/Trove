# Trove v1.2.9 — Real Test Wiring

## Goal
Prepare Trove for two independently verifiable real-provider test flows without mixing payment responsibilities.

## Changes
- Booking.com v3.2 create payload now follows the current top-level `booker` structure and v3.2 address fields.
- Booking flow passes the traveller address through to the provider adapter.
- Real beta preflight refuses the unsafe combination of full Trove/YooKassa collection with Booking.com `pay_at_property`.
- Real beta preflight refuses raw-card Booking.com online payment unless an explicitly approved PSP/tokenized/VCC source is configured.
- Added `docs/REAL_TEST_SETUP.md` with credential, sandbox and payment-model requirements.
- Added `deploy/.env.real-test.example`.

## Verification
- Shell syntax checks pass.
- Source changes were inspected statically.
- Full TypeScript/build/E2E execution is not claimed because dependencies and provider credentials are not present in the current environment.

## Required external setup
### YooKassa
- Test shop
- Test shop ID
- Test secret key
- Optional public HTTPS callback for webhook testing

### Booking.com
- Managed Affiliate Partner access
- Partner Centre
- Demand API key
- X-Affiliate-Id
- Native booking/order access
- Correct payment agreement if using online payment

## Important
YooKassa customer payment and Booking.com supplier payment are separate commercial/payment responsibilities. A `pay_at_property` Booking.com order must not be preceded by a full-price YooKassa charge in Trove. For an OTA merchant-of-record flow, Booking.com documents a VCC-based partner-collects model that requires the appropriate Booking.com payment agreement and VCC capability.

## UI redesign pass

The v1.2.9 frontend now includes a full consumer-facing travel marketplace redesign:

- visual hero with large destination photography;
- country/city destination autocomplete with flags;
- popular destination shortcuts;
- adults + children guest picker with increment/decrement controls;
- date range inputs;
- search-button loading state;
- richer homepage with benefits, destination cards, offer grid, hot-offer banner and guide section;
- richer tour cards with Trove Score and additional trip details;
- improved responsive header/navigation;
- shared button loading state;
- responsive mobile layouts.

The design remains intentionally lightweight: no Tailwind, no UI framework, SCSS + Vue components.

The environment did not contain `node_modules`. An attempt to install frontend dependencies timed out, so a full Nuxt build/typecheck was not run. The changes were inspected statically and the release archive was checked for expected files.
