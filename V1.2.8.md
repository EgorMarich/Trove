# Trove v1.2.8 — Real Provider E2E

This release adds an explicit real-provider E2E harness for Booking.com Demand API v3.2 sandbox and YooKassa test API.

## Booking.com
- sandbox-only guard for the automated real E2E journey;
- availability → preview → create → details → cancellation;
- request_id is logged at every order boundary;
- cancellation uses the v3.2 `accommodation.reservation` payload;
- confirmed sandbox orders are cancelled automatically for cleanup.

Booking.com documents the v3.2 accommodation lifecycle as current availability → `/orders/preview` → `/orders/create`, with `/orders/details/accommodations` for post-booking state. The preview token expires after 15 minutes. Cancellation uses `/orders/cancel` and an accommodation reservation identifier.

## YooKassa
- authenticated API probe;
- optional explicit test payment creation;
- test payment creation requires `YOOKASSA_ALLOW_TEST_PAYMENT=I_UNDERSTAND_TEST_PAYMENT` to avoid accidental payment creation.

## Commands

```bash
pnpm real:preflight
RUN_BOOKING_REAL_E2E=true pnpm real:e2e
RUN_YOOKASSA_TEST_PAYMENT=true YOOKASSA_ALLOW_TEST_PAYMENT=I_UNDERSTAND_TEST_PAYMENT pnpm real:e2e
```

No real credentials are bundled. The E2E scripts refuse to pretend that a provider is available when credentials are missing.
