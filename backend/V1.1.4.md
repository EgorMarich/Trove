# Trove v1.1.4 — Provider Order Persistence & Reconciliation

## Goal
Make the provider-order boundary durable and make recovery safe against duplicate reservations.

## Added
- `providerOrderRepository` with PostgreSQL + in-memory fallback.
- Migration `003_provider_order_persistence.sql`.
- Durable provider order status: `created | pending | confirmed | cancelled | unknown`.
- Provider order/request identifiers are persisted independently from the booking row.
- Booking confirmation records provider order state before marking the booking confirmed.
- Provider failures create an `unknown` provider-order boundary.
- Recovery reconciles an existing remote order through the provider before any retry.
- Unknown remote order state goes to manual review instead of blindly creating another reservation.

## Important safety property
If a provider request may have succeeded but the response was lost, Trove does **not** automatically create a second order. It first requires an authoritative provider lookup or manual review.
