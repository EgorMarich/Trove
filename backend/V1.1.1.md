# Trove v1.1.1 — Auth Repository Migration

## Goal
Move the identity boundary from direct in-memory maps to a repository that can persist users, sessions and verification tokens in PostgreSQL without changing the auth business API.

## Implemented
- `authRepository` with PostgreSQL persistence.
- In-memory fallback when `DATABASE_URL` is absent.
- User CRUD required by auth flows.
- Server-side session persistence and expiry checks.
- Verification/password-reset token persistence.
- Atomic verification-token consumption.
- PostgreSQL unique-contact conflict handling.
- Auth services converted to async repository calls.
- HTTP auth/session endpoints updated for asynchronous persistence.
- Existing `authStore` kept only as a compatibility alias.
- Repository smoke test added as `pnpm test:auth`.

## Database tables used
- `users`
- `sessions`
- `verification_tokens`
