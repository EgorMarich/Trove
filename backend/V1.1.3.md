# Trove v1.1.3 — Payment Repository Migration

## Goal
Move Trove payment intent state and payment lifecycle events from process memory to PostgreSQL.

## Changes
- `paymentStore` now supports PostgreSQL persistence with the existing in-memory fallback.
- `payment_intents` is the durable source of truth for payment intent state.
- `payment_events` stores the complete payment lifecycle.
- Verified webhook event IDs are persisted as payment event IDs, making webhook idempotency survive backend restarts.
- Payment status transitions are written transactionally with their lifecycle event.
- Provider payment references and failure reasons are persisted.
- Added indexes for payment event lookup and provider payment reconciliation.

## Current boundary
```text
Payment Service
      ↓
Payment Store
      ↓
PostgreSQL
      ↓
payment_intents + payment_events
```

The mock payment provider itself still keeps its simulated remote state in memory. That is intentional for the local test provider. A real PSP adapter will be the remote source of truth in production.
