# Trove v1.1.8 — Booking.com Sandbox Integration

This release prepares and validates the real Booking.com Demand API v3.2 accommodation journey against the official sandbox.

## Flow

```text
/accommodations/search
        ↓
/accommodations/availability
        ↓
/orders/preview
        ↓
/orders/create
        ↓
/orders/details/accommodations
```

The adapter now carries the traveller contact context required by the provider boundary, including telephone and optional address fields.

## Sandbox test

Set:

```env
BOOKING_API_BASE_URL=https://demandapi-sandbox.booking.com/3.2
BOOKING_API_KEY=...
BOOKING_AFFILIATE_ID=...
BOOKING_NATIVE_BOOKING_ENABLED=true
BOOKING_SANDBOX_ACCOMMODATION_ID=10507360
BOOKING_BOOKER_COUNTRY=nl
BOOKING_CURRENCY=EUR
BOOKING_PAYMENT_TIMING=pay_at_property
BOOKING_PAYMENT_METHOD=pay_at_property
```

Then run:

```bash
pnpm test:booking-sandbox
```

The script deliberately fails when credentials are missing instead of silently using mocks.

The default sandbox accommodation ID comes from Booking.com's published Demand API sandbox documentation. The sandbox is non-production and uses test inventory; production inventory must never be mixed with sandbox IDs.

## Important

Real Booking.com order creation requires partner access/permission and current provider credentials. This repository contains the integration boundary and a real HTTP sandbox harness, but no credentials are bundled.
