# Trove v1.0.2 — Booking Orchestrator & Payment Boundary

## Delivered
- Booking lifecycle/state machine: draft → previewed → pending_payment → provider_booking → confirmed.
- Failure states: expired, price_changed, payment_failed, provider_failed, failed.
- Booking preview endpoint with idempotency and 15-minute preview token.
- Mandatory second price check before confirmation.
- Provider booking boundary separated from payment boundary.
- Provider order ID and request ID stored on Trove booking.
- Immutable-style lifecycle event log in the current in-memory store.
- Booking lifecycle events endpoint.
- Mock native booking adapter now returns a created booking for development.
- Native provider confirmation remains required; no fake success when provider capability is unavailable.
- Payment card data is not handled or stored by Trove.

## API
- POST /api/bookings/preview
- POST /api/bookings/:id/confirm
- GET /api/me/bookings/:id/events
