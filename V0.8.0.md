# Trove v0.8.0 — Loyalty & Promotions

## Delivered
- Promotion domain with fixed and percentage discounts.
- Promotion validation endpoint with expiration, usage limits, minimum amount, destination and new-customer rules.
- Loyalty profile derived from booking history.
- Explorer / Traveler / Voyager levels with 0% / 3% / 5% personal discount.
- Personal discount does not stack with a promo code in v0.8.
- Booking creation accepts a validated promo code and stores original price, discount and applied code.
- Promotion usage is recorded only after successful booking creation.
- `/api/me/loyalty`, `/api/promotions`, `/api/promotions/validate` endpoints.
- Account page now exposes Trove Club status and active promotions.
- Booking page supports promo-code validation and shows loyalty discount.
- Booking history/detail shows applied discounts.

## Production follow-up
- Move promotions, loyalty and usage to PostgreSQL.
- Add admin CRUD and campaign targeting.
- Add immutable pricing/discount ledger.
- Add currency-aware rounding and tax/fee rules.
- Define provider commission margin before allowing discounts in production.
- Add transactional usage reservation to prevent concurrent promo overuse.
