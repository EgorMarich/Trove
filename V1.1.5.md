# Trove v1.1.5 — Production Security Hardening

This release closes the next production-readiness boundary after durable auth, booking, payment and provider-order persistence.

## Included
- Redis-backed rate limiting with in-memory development fallback.
- Secure response headers and production HSTS.
- Same-origin validation and double-submit CSRF protection for authenticated state-changing requests.
- CSRF-aware frontend API helper.
- Production environment validation.
- Durable PostgreSQL audit event table with safe in-memory fallback.
- Production session cookie remains `__Host-trove_session`.

## Launch requirements
- HTTPS.
- `FRONTEND_ORIGIN` must be the exact HTTPS origin.
- `DATABASE_URL` configured and `DATABASE_SSL=true`.
- `REDIS_URL` configured.
- Run database migrations before starting the API.
- Configure real payment/provider credentials only through server-side environment/secret storage.

## Not claimed
Dependencies, type-check, lint and integration tests were not executed in this environment because project dependencies are not installed here.
