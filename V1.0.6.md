# Trove v1.0.6 — Booking.com Sandbox Test Harness

## Delivered

- Introduced an injectable Booking.com HTTP transport boundary.
- Added deterministic provider fixtures for `orders/preview`, `orders/create`, and `orders/details/accommodations`.
- Added a runnable TypeScript contract harness covering:
  - preview token and price extraction;
  - order creation and provider IDs;
  - confirmed reconciliation;
  - not-found reconciliation;
  - request path/order assertions.
- Added `pnpm test` script for the provider harness.

## Why

The real Booking.com sandbox credentials are optional. The harness verifies the adapter contract without making network requests, so provider integration changes can be tested deterministically before live credentials are available.

## Production follow-up

- Add HTTP timeout and AbortController.
- Add schema validation for provider responses.
- Add retry policy only for explicitly retryable provider failures.
- Add full integration tests against Booking.com sandbox once partner credentials are available.
- Never put provider API keys or customer payment data into fixtures.
